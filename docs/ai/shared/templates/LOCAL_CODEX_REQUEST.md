# ローカルCodex依頼（頭脳が出す。ユーザーは貼るだけ）

RULES §8の19・§5の13の2。1つのコードブロックで出す。末尾の定型文はCloud Codexへの依頼にも同じものを使い、Projectごとに書き写さない。ユーザー操作欄は「このプロンプトをローカルCodexへ貼る」。GitHubに置けるProjectで依頼が長いときは、依頼をTASKファイルにしてpushし、`templates/CODEX_LAUNCH.md` の一言で起動する（RULES §8の19の2）。この貼付形式は、GitHubに置けない・pushできない場合の既定。

```
Project／TASK: <名前>／<TASK-NNN>
目的: <何を確かめる／実行するか。1〜2行>
対象: <repo>、branch <名前>、コミット <40桁SHA>（checkout後にSHA一致を確認）
環境: <OS、必要な道具、開発用の構成であること。パス・秘密は書かない>
手順:
1. <コマンドまたは操作>
2. <期待する観測。ログ・画面・出力>
証跡: コマンド・出力・スクリーンショット、対象SHA・build、時刻、環境を報告に残す。ログは確認した実行の時刻と合うものを使う。
守る範囲: <read-onlyか。変更してよいファイル>。認証・権限・branch protection・main・tagに触れない。pushしない（TASKで指示があるときを除く）。失敗は修正せず報告する（TASKで指示があるときを除く）。
独立レビューの基準（risk_paths に触れた、解釈を選んだ箇所がある等）に当たる場合は、ユーザーに聞かずに、別の実行で独立レビューを実施し、結果と採否を完了報告に含めてください。CI は実行せず、推奨の判断だけを出してください。最終メッセージは、頭脳へそのまま貼れる1つのコードブロックにまとめてください（結論／返却理由／対象SHA／根拠／残課題／CIの推奨）。人が見る情報はブロックに入れず、ブロックの外に、短い一言・実行表（役割｜モデル｜負荷｜状態・結果。1行目はMain自身、続けてサブ1回につき1行、サブなしなら「サブなし」）・渡し先（例: 頭脳へ貼る）を必ず書いてください。
```
