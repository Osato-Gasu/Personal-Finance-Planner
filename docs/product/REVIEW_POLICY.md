# 実装レビュー方針 v0.2

## 1. 回数

同一TASKの実装レビューは最大3回とする。

- 第1回: 全要件・全受入条件を厳密に判定
- 第2回: 第1回の必須指摘を修正後、同じ非緩和条件で再判定
- 第3回: 第2回も不通過の場合に限り、緩和可能項目を限定して最終判定
- 第3回不通過: レビュー打ち切り、未解消事項を固定しユーザー判断へ移す

不通過回数は同一TASK・同一実装目的で数える。candidateを差し替えても回数をリセットしない。

## 2. 緩和可能項目

第3回だけ、製品安全・計算結果・データ保全へ影響しない範囲で緩和できる。

- 非必須UIの微調整
- 文言の軽微な改善
- 任意のアニメーション
- 非必須グラフ
- 軽微なコード整理
- 性能目標を満たしている場合の追加最適化
- 必須内容を欠かない補助文書の表現

緩和した項目は`deferred`として記録し、承認済みと偽装しない。

## 3. 緩和禁止項目

- 税・社会保険・NISA・iDeCo・家計計算の正確性
- 制度ruleの対象年月・対象者
- 未対応条件の明示
- 金額・割合の端数と合計整合
- 連携値の正本管理
- stale data防止
- 二重計上防止
- 保存、migration、importのデータ保全
- XSS等の基本セキュリティ
- build、test、lint
- TASKの必須受入条件
- ユーザー所有差分の保護
- branch、candidate、baselineの同一性

## 4. 判定

- `APPROVED`
- `CHANGES_REQUESTED`
- `BLOCKED`
- `NEEDS_USER_DECISION`

第3回不通過時は`CHANGES_REQUESTED`を繰り返さず、`NEEDS_USER_DECISION`または外因があれば`BLOCKED`へ遷移する。

## 5. 記録

各レビューで次を残す。

- review attempt: 1 / 2 / 3
- candidate commit・tree
- 実行したtest
- finding
- mandatory / relaxable
- 採否
- 次の遷移
- 第3回で緩和した項目
- 打ち切り時の未解消事項

## 6. 設計レビュー

本方針の3回制限は実装レビューに適用する。制度変更や重大な設計安全性に関する設計レビューは、必要に応じてユーザー判断へ直接移せる。
