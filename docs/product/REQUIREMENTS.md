# 要件定義 v0.3

## 1. 製品識別

- アプリ表示名: 暮らしと資産プランナー
- 英語名: Personal Finance Planner
- repository: `Osato-Gasu/Personal-Finance-Planner`
- 対象地域: 日本
- 対象利用者: 個人、本人と同棲相手または配偶者の最大2名
- 位置付け: 家計・手取り・資産形成の概算支援ツール

## 2. 目的

利用者が次の順序で現在と将来のお金を把握できることを目的とする。

1. 基本給、平均残業、固定手当、賞与から対象年の総支給を概算する。
2. 給与・賞与から法定控除後の手取りを概算する。
3. 日・週・月・年単位で発生する生活費を月額等へ平準化する。
4. 同棲時の共同費を全体、カテゴリ、費目ごとの割合で分担する。
5. NISA・iDeCoへの拠出後に残る金額を確認する。
6. 積立元本、運用益、将来残高、制度上限を試算する。
7. 保存した基準日の投資後手残りと明示的なライフイベントから、暦年ごとの現預金残高を固定シナリオとして確認する。
8. 同じ暦年12月末の現預金、NISA、iDeCoと、それらの拠出時期が整合する場合だけ金融資産合計を確認する。

## 3. 画面構成

トップレベル画面はURLを持つSPAページとし、見た目をタブ型ナビゲーションにする。

| 画面         | route           | 主目的                             |
| ------------ | --------------- | ---------------------------------- |
| 総合サマリ   | `#/overview`    | 全モジュールの主要結果を統合表示   |
| 給与計算     | `#/payroll`     | 基本給、残業、手当、賞与の概算     |
| 手取り計算   | `#/take-home`   | 給与、税、社会保険、手取りの概算   |
| 家計簿       | `#/budget`      | 支出平準化、カテゴリ、負担割合     |
| NISA + iDeCo | `#/investments` | 積立、上限、将来資産、節税効果     |
| 設定         | `#/settings`    | 人物、制度年月、保存、バックアップ |

再読み込み、戻る、進む、URL直開きに対応する。画面切替で保存済み入力を失わない。旧`#/life-plan`は`#/overview`へ正規化し、ライフプラン機能は総合サマリ内の「将来資産シミュレーション」に保持する。

### 3.1 起動・配布

- 開発sourceは`index.html`、TypeScript、CSS、その他moduleへ分離する。
- 開発時は`npm run dev`でViteを利用する。
- `npm run build`はJavaScript、CSS、必要な静的assetをinlineしたstandalone `dist/index.html`を生成する。
- end user向け通常起動ファイルは常設main folder直下の`Personal-Finance-Planner.html`とし、ダブルクリックだけで`file://`起動できる。
- `Personal-Finance-Planner.html`はstandalone buildから決定的に生成・同期するGit管理対象であり、第二のsource of truthとして手編集しない。source buildに対してstaleならCIを失敗させる。
- `dist/index.html`は内部build artifactとして維持できる。
- ビルド済みアプリの利用時にHTTP server、Node.js、npmを必要としない。
- root launcherだけを空白・日本語を含む別folderへコピーしても起動する。
- runtime CDN、外部script、外部stylesheet、modulepreload、dynamic import、外部network requestへ依存しない。
- routingはhashだけを使用し、file pathをrouteとして扱わない。
- Windows 10／11上のChromium系browserを初期対象とする。
- 同じfile pathではlocalStorageのStateをreload後も復元する。
- HTMLの移動・folder名変更・file名変更によりbrowserの保存領域が変わる可能性を利用者へ明示する。

## 4. 共通プロフィール

最大2名を管理する。

- 本人
- 同棲相手または配偶者

人物ごとに表示名、生年月日、居住都道府県、収入計画、NISA計画、iDeCo計画を保持する。NISA・iDeCoの上限判定と資産は人物単位とし、世帯合算値は表示専用とする。

## 5. 総合サマリー

次を月額中心に表示する。

- 額面収入
- 法定控除後手取り
- 生活費
- 生活費後手残り
- NISA拠出額
- iDeCo掛金
- 投資後手残り
- 本人と相手それぞれの負担額・手残り
- NISA・iDeCoの元本、運用益、想定残高
- 適用制度、制度確認日、未対応条件
- 支出超過、制度上限超過、古い制度データ、バックアップ未実施の警告

3種類の残額を混同しない。

```text
法定控除後手取り = 額面収入 - 税 - 社会保険料
生活費後手残り = 法定控除後手取り - 生活費
投資後手残り = 生活費後手残り - NISA拠出 - iDeCo掛金
```

### 5.1 給与計算と連携パイプライン

給与計算は対象年ごとの`PayrollPlan`を正本とし、基本給だけを残業単価基礎として、整数分・basis points・BigInt有理数のround-half-upで残業代を計算する。平均残業は12か月反復する概算であり、深夜・休日・60時間超の区分を自動化しない。

同一人物・同一年の給与計画は`TakeHomeCompensationBinding`で手取り計算へ連携できる。連携中はpersist済み直接入力を変更せず、給与結果から月次modeの一時的なcompensationを作る。賞与は一度だけ含め、不正・欠落・曖昧な連携は直接入力へfallbackしない。

家計収入は`BudgetIncomePolicy`により、従来の手入力／`LinkDefinition`または対象年の唯一のactive計算手取りを選ぶ。autoで0件、複数、未計算なら利用不可とし、手入力0円へ置換しない。家計簿後の残額は「投資可能額」であり、自動投資額ではない。

## 6. 家計・生活費

### 6.1 カテゴリ

追加、編集、並び替え、無効化、削除を行える。

- カテゴリ名
- 説明
- 既定負担割合
- 表示順
- 有効状態

費目が所属するカテゴリは直接削除させず、別カテゴリへの移動または無効化を要求する。

### 6.2 費目

次を入力する。

- カテゴリ
- 用途
- 1回あたりの出費
- 周期値
- 周期単位: 日、週、月、年
- 周期内回数
- 費目範囲: 共同、本人、相手
- 負担割合: 継承または個別
- メモ
- 有効状態

追加、編集、複製、無効化、削除、検索、絞り込み、並び替えを行える。

### 6.3 負担割合

共同費だけに適用し、優先順位は次とする。

```text
費目設定 > カテゴリ設定 > 世帯全体設定
```

本人側を0.1%単位で入力し、相手側は100%との差分として求める。個人費とNISA・iDeCoには共同費の割合を適用しない。

### 6.4 入力モード

- 詳細集計: 費目の平準化額を合計
- 簡易集計: 月間生活費合計を直接入力

モード切替で既存費目を削除しない。簡易集計ではカテゴリ・費目別割合を使わず、世帯全体割合だけを使う。

## 7. 手取り計算

### 7.1 初期対象

- 日本国内の給与所得者
- 本人と相手を個別計算
- 年収入力または月給・賞与入力
- 所得税、住民税、厚生年金、健康保険、介護保険、雇用保険の概算
- iDeCo掛金控除
- 協会けんぽ、または社会保険料手入力

### 7.2 明示的な非対応

組合健保、共済組合等を選んだ場合に協会けんぽ料率を自動適用しない。次のいずれかを要求する。

- 保険料を手入力する。
- 未計算のまま結果から除外し、未対応警告を表示する。

### 7.3 入力

- 対象人物
- 対象年月
- 生年月日
- 居住都道府県
- 年間給与または月給
- 賞与
- 非課税通勤手当
- 前年所得
- 扶養・配偶者・障害者等の控除条件
- 生命保険料控除等
- iDeCo掛金
- 健康保険種別
- 必要な手入力保険料

### 7.4 出力

- 額面収入
- 給与所得
- 各税・社会保険料
- 年間手取り
- 月平均手取り
- 控除率
- iDeCo適用前後の税額差
- 計算できなかった項目
- 適用した制度ルール

実際の給与明細との差が生じる要因を結果画面に表示する。

## 8. NISA・iDeCo

### 8.1 共通

- 対象人物
- 開始年月
- 終了年月または目標年齢
- 現在残高
- 取得額または拠出元本
- 毎月積立
- 臨時拠出
- 想定年利
- 年間費用率
- インフレ率
- 月初・月末拠出
- 弱気、標準、強気の保存可能なシナリオ

アプリは商品や利回りを推奨しない。

### 8.2 NISA

制度ルールから次を検証する。

- 年間投資枠
- 枠種別
- 生涯または保有限度
- 対象年月
- 人物ごとの使用額

元本、運用益、想定残高、枠残量、枠を使い切る時期を表示する。MVPでは売却による翌年以降の枠再利用は対象外とする。

### 8.3 iDeCo

加入区分、企業年金等の有無・掛金相当額、本人掛金、現在残高、手数料、受取開始年齢を入力する。

- 制度上限
- 年間掛金
- 元本
- 運用益
- 想定残高
- 所得税・住民税の推定軽減額
- 税軽減後の実質負担

受取時課税を実装するまでは、想定残高が受取税引前であることを明示する。

## 9. ライフプラン年間キャッシュフロー

ライフプランは、保存した基準日の世帯「投資後手残り」を12倍した固定年間キャッシュフローへ、利用者が登録したライフイベントを暦年単位で加減算するMVPとする。給与、税、社会保険、生活費、投資額、制度または運用成果の将来変化は自動予測しない。

- `baseReferenceDate`: 上流の総合計算を固定する実在する日付。現在時刻から再解釈しない。
- `projectionStartYear`: 開始時現預金残高が1月1日時点で所属する年。
- `startingLiquidAssetsYen`: 開始年1月1日の0円以上の安全な整数残高。
- `projectionYears`: 1～60年。終了年は9999年を超えない。
- イベント: 安定ID、名称、収入／支出、開始年、終了年、年間金額、メモ、有効状態を持つ。開始年と終了年を含む各年に適用し、支出額は正数で保存して計算時に減算する。

基準日、開始年または上流の投資後手残りが未確定なら0円へ置換せず`incomplete`とする。円の乗算、イベント合計または累積残高が安全整数範囲を超えたら`out-of-range`として後続行を生成しない。負の期末残高は有効な結果として保持し、最初の年を文字でも警告する。

画面には固定シナリオであり将来制度予測ではない説明を常時表示する。設定は4項目を一括保存し、不正値ではStateとstorageを変更しない。イベントIDは更新で変更できず、存在しない更新・有効切替・削除は拒否する。編集bufferは明示保存まで永続化しない。

同じ画面で、各投影年`Y`の正確な`Y-12`をendpointとして、TASK-014の年末現預金とactive人物のNISA・iDeCo名目残高を表示する。投資計画の目標が12月より前なら目標月残高を年末値へ凍結・外挿せず、開始が12月より後なら過去残高を推測しない。既存投資計算が`complete`以外、制度rule欠落、範囲外または複数active計画なら、失敗した投資残高を0円へ置換しない。

TASK-015のiDeCo評価は、保存済み`baseReferenceDate`とその年から作る同一の基準日・税年contextを全投影行で使用する。年末samplingは月次投影点だけを選択し、行末日、目標日または現在時刻をiDeCo税診断の基準へ代用しない。

金融資産合計は次の場合だけ数値とする。

```text
金融資産合計
= 年末現預金 + NISA年末残高 + iDeCo年末残高
```

- active人物・domainごとの投資年末残高が`complete`または未設定0円である。
- `baseReferenceDate`の総合計算に含まれる人物別NISA・iDeCo月額拠出と、投影開始年1月から行末までの実計画拠出が毎月1円単位で一致する。
- iDeCo固定月額費用は投資口座内の費用として扱い、世帯の外部拠出比較へ含めない。
- 年末現預金が0円以上で、安全整数の加算が成功する。

最初の拠出不一致月を人物・domain・sourceとともに保持し、その月を含む行以降は、後に再一致しても金融資産合計を`—`とする。投資拠出を現預金から再度差し引かず、投資残高へ元本を重ねて加算しない。負の現預金は不足額として表示するが金融資産合計を数値にしない。この合計は表示対象の金融資産だけで、負債を含む純資産ではない。年次結果はruntime導出のみとし、schemaVersion 8でも永続化しない。

## 10. ツール間連携

各値の正本を固定する。

| 値               | 正本           |
| ---------------- | -------------- |
| 額面給与・賞与   | 給与計算       |
| 法定控除後手取り | 手取り計算結果 |
| 生活費           | 家計簿         |
| NISA拠出         | NISA計画       |
| iDeCo掛金        | iDeCo計画      |
| 投資後手残り     | 総合計算結果   |
| 年間固定手残り   | 保存基準日の総合計算結果 |
| NISA年末残高     | NISA計画の同一評価経路にある`YYYY-12`投影点 |
| iDeCo年末残高    | 固定基準日contextを使うiDeCo計画の同一評価経路にある`YYYY-12`投影点 |

連携値はコピー保存せず、正本への参照から再計算する。正本更新時は連携先へ即時反映する。手入力へ変更する場合だけ、利用者が明示的に連携解除する。

生活費と資産形成拠出を別データ種別にし、名称や金額の類似比較ではなく`sourceType`と`sourceId`で構造的に二重計上を防ぐ。

## 11. 保存とバックアップ

- localStorageへはRepositoryだけがアクセスし、有効なState遷移だけを保存する。
- current AppStateはschemaVersion 8とする。v7境界を凍結し、v7→v8では空の`payrollPlans`、`takeHomeCompensationBindings`、`budgetIncomePolicies`だけを追加し、旧`life-plan` routeを`overview`へ写像する。v1～currentを決定的かつidempotentに移行する。
- current keyは`personal-finance-planner:state:v8`とし、v8が存在する場合は壊れていてもv7以下へfallbackしない。v8がなく有効なv7以下がある場合だけv8へ移行保存し、legacy bytesを変更しない。
- migration前のlegacy bytesを削除・上書きしない。migration失敗時はlegacy/current双方を変更せず、corrupt currentを古いlegacyへ黙ってfallbackして上書きしない。
- schema v1のotherwise-validな表示名に含まれるLF、CR、CRLF、前後空白、50文字超、日本語・記号をlosslessに保持する。単一行inputのDOM正規化値を自動write-backせず、明示的な名前編集と保存が行われた場合だけ置換する。
- JSON exportはvalidate済みcurrent AppStateだけをUTF-8で生成し、derived resultを重複保存しない。JSON生成とbrowser file handoffが成功した場合だけ`lastExportedAt`を更新する。
- JSON importは`read bytes → size limit → parse → schema判定 → in-memory migration → schema validation → invariant validation → preview → confirmation → atomic replacement`の順序とする。confirmation前、cancel、失敗時のwriteは0件とする。
- unknown keyのblind merge、prototype pollution、unsafe integer、broken active link、member mismatchを拒否する。
- 最終backup日時と設定期間からwarningを導出する。dismissは期限付きとし、`lastExportedAt`やbackup成功を偽装しない。
- 複数端末同期は対象外とし、端末間移行はJSONで行う。networkへ金融データを送信しない。

## 12. 非機能要件

- 金額は円単位整数で保持
- 負担割合はbasis pointsで保持
- 計算ロジックをDOM・保存処理から分離
- 同じ入力・同じルールでは同じ結果
- 360px以上の画面幅に対応
- キーボード操作、フォーカス表示、ラベル関連付け
- `#/settings`で人物、JSON export/import、backup reminder、保存状態、schema/version、データ保全と`file://`保存領域の注意を扱う。
- expected errorは操作付近へ表示し、whole-page crashやStateの0/default置換を行わない。destructive importは確認を必須とする。
- 色だけで状態を表現しない
- ユーザー入力を未エスケープHTMLとして挿入しない
- 初期版の実行時外部依存を持たない
- standalone HTMLの実行時にdocument本体以外のnetwork requestを行わない
- ビルド、テスト、lintをCIで実行
- 計算結果に概算・適用制度・未対応条件を表示

## 15. 全体受入条件

- 各画面をURLから開き、戻る・進むが機能する。
- 画面切替で保存済みデータを失わない。
- 本人と相手のデータ・制度枠を混同しない。
- 費目を日・週・月・年で平準化できる。
- 負担割合の3階層優先順位が機能する。
- 2名の負担額合計が共同費合計と一致する。
- 連携値が正本更新後に自動更新される。
- 連携解除なしに手入力で連携値を上書きできない。
- NISA・iDeCo拠出を生活費と二重計上しない。
- iDeCo控除効果と掛金を二重計上しない。
- 制度有効期間の境界日で正しいルールを選ぶ。
- ルール期間の重複・空白を検出する。
- 未対応保険種別に協会けんぽ料率を適用しない。
- 不正JSONで現在データを失わない。
- 再読み込み後にデータを復元できる。
- 最終バックアップ日時と通知が機能する。
- v1～currentのmigrationと再migrationがlossless、deterministic、idempotentで、失敗時に既存bytesを変更しない。
- v1表示名のLF、CR、CRLFがsettings表示、無関係保存、reload、export/importでsilent mutationせず、明示編集時だけ変更される。
- import preview・confirmation前・cancel・失敗時はwrite 0で、成功時だけatomic replacementする。
- `Personal-Finance-Planner.html`が常設main folder直下でfreshに生成され、ダブルクリックと単体コピーで起動する。
