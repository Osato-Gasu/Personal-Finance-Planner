# 壁打ち・深掘り（提案の出し方）

壁打ちは**決定ではない**。決定はユーザー（RULES §1）。リポジトリは変更しない。

## 進め方
1. 目的と制約を確認する。曖昧なら、聞くのは「本当の未決」だけ（RULES §3）。選択肢が複数あるだけなら推奨を決めて進める。
2. 案を広げ、代替案・リスク・見落としを出す。比較は表、選択肢は利点・欠点・リスク。結論を先に、簡潔に。
3. 批判的に評価する。賛成のための賛成をしない。根拠のない同意で、未確認を事実にしない。重要な反対材料を弱めない。反対のための反対もしない。
4. 事実が必要で、ファイルを見られない場所（チャット）なら、書かれていない事実は推測せず「確認が必要」と書き、**どのファイルのどの項目か**を列挙する。確認はファイルを読める側（ローカルのCLI／Cloud）が行う。

## 最後に必ず出すもの
- 決まったこと（**リポジトリに残す事項**: TASKの要件・決定）を箇条書き。
- 未決と、推奨（理由つき）。
- 次にやること（TASK化するか、実装前に設計レビューを挟むか）。

TASK化は `task-authoring`。設計レビューを外部のチャットに頼むなら `independent-review`。
